## 本来测什么，本轮回答到哪里

给定正常包 README、全部公开 TS 入口和源码检索，模型能否找到接口、组合接口、正确理解结果与清理责任。任务使用调用方给定对象和明确类型契约；这不是完全无提示的 API 发现实验。

## 逐题结果

| 任务 | 提交/调用方编译 | 静态标准 | 结果 |
|---|---|---|---|
| 筛选并累计支付金额 | 通过 | 3/3 | 满足冻结要求；正确保留 0、负数及 seed 与首个 DATA 的区别 |
| host push 接入与订阅清理 | 通过 | 2/3 | 代码符合本题使用方式，但激活时机的解释自相矛盾 |
| 有限深度下游查询 | 通过 | 2/3 | 正确调用 helper 并保留结果，但截断语义的反例解释错误 |
| 单页审计日志读取 | 通过 | 3/3 | 正确保留 seq=0、amount=0、游标及当前读取的 done |

**push 题：**解释同时说“注册发生在首次订阅”和“register 不在 connectPushNumbers 调用时发生”。实际提交的函数内部同步调用了 `source.subscribe`，因此注册及同步 `onValue` 可以在该函数返回之前发生。复核考虑了答案中正确的订阅说明；明确错误的时机断言仍违反冻结的激活解释标准。没有把它记成编译失败或实现缺陷。

**查询题：**答案正确给出三节点图的三个结果，也正确透传 `truncated`。但它用两节点环的 depth=0 说明“没有尚未访问的节点”：此时 walk 尚未返回 B，B 实际上还未被遍历。能说明该标志保守性的关键情形是 depth=1：B 已访问，B 的唯一邻居 A 也已访问，标志仍为 true，因为 helper 在检查 seen 之前检查边界邻接。扣分依据是解释错误，不是必须逐字复述标准答案。

评分及证据见 [review-verified-summary.json](live/review-verified-summary.json) 和四个 `candidate-entry-0N.review-input.json`；原始代码和响应位于 [outcome.json](live/outcome.json) 指向的不可覆盖运行目录。复核再次编译原始提交与隐藏调用方探针，并校验 assessment/compilation 绑定。

## 对 library 的反馈

当前证据支持改进文档的具体假设，不支持“库实现有 bug”或大范围 API 重设计。

1. **把 push 激活时序写成完整调用示例。** `fromPushNotification` 当前公开 JSDoc 的示例只有 import，参数说明也没有交代同步回调。建议增加“创建 factory → graph 注册 → subscribe 同步激活 → register 可同步发 DATA → 返回 unsubscribe”的例子，并展示另一个订阅者存在时 stop 的边界。目的在于避免把 lazy factory 等同于包含 subscribe 的包装函数也延后执行。
2. **为 `ReachableResult.truncated` 增加两节点环反例。** 当前“still-expandable frontier”容易被读成“确实存在未见节点”。建议直接说明它表示深度边界上仍有邻接，不保证有未访问节点，并给出 A↔B、start=A、depth=1 的结果。维持已有行为；本轮没有改变诊断语义。
3. **保留已奏效的公开组合方式。** 模型经 README 和公开入口正确完成 filter/scan 与日志分页。只有两个样本，不能据此宣布设计普遍易懂，也没有理由为本轮增加新 factory 或额外 abstraction。

后续文档/库修订应作为新版本保留差异；本轮四题可作为已暴露回归题，不能重新包装成独立新题。下一轮仍应预先固定任务、预算、评分和停止条件。不要通过反复解释这两道题直至全绿来证明改进有效。

- 本轮唯一生产 harness 改动：允许真实 scoped 根入口 `@graphrefly/ts`，同时继续拒绝不合法别名及越界路径。统一映射 71 个公开 TS 入口；另纳入 2 个资源导出。
- 288 份材料包括包 README、package.json、生产 TS/source README。未包含评分、探针、校准答案或旧评测记录；真实 broker 隔离探针通过。README 的两个 sibling example 链接未纳入本轮，不能声称完整网站/例程文档闭包。
- 根仓库测试 **233/233**；71 个公开 import 同时编译通过；12 个正/反例编译预期匹配；4 个正例经独立调用方编译检查通过。编译并不能验证运行时行为，语义反例另需静态判读。
- 未改 TS library 的实现或协议；原始脏工作区变动已对照本轮开始时的基线核验。没有提交、推送或发布。
- `concepts` 是继承的自报字段，未用它证明理解或参与评分；它与这轮一般 API 任务的相关性有限，未来收束问卷时应单独处理。
- 初次离线 wrapper 缺少 receipt 父目录，以及第一次评分输入漏填 assessment hash，均在本地被拒绝并留下记录；随后补全包装层输入，未修改冻结材料、评分或参与者答案，也未触发额外付费任务。
- 任务作者与根复核者分离，但根复核者也是 harness 作者；额外独立 reviewer 因 agent 数量限制不可用。完整 QA 的独立性不足，不作盲审声明。
