# GraphReFly internal dashboard — data contract

The dashboard is **for the maintainer** (not end-users): see global state, progress,
structure map, and gaps in one place, with search. Data source = the jsonl files
across this repo. UI is generated by `build.mjs`. Styling is a separate `/frontend-design`
pass — `build.mjs` only produces the data model + a placeholder shell.

> **Why jsonl + generated HTML:** jsonl is the single source of truth (decision 2). Prose
> docs (spec section intros / guide / session bodies) stay markdown but each has a jsonl **index row**
> so the dashboard can index/search/link them. Eventually (CSP-8) the dashboard itself is
> rebuilt *with GraphReFly* — jsonl as producer → reactive views → HTML effect (the
> "messaging-hub reactive jira" internal Workbench).

## jsonl schemas (source of truth — jsonl files carry NO comments)

### `decisions/decisions.jsonl`
```
{ id:"D7"|"DR-1", layer, date, question, decision, rationale, supersedes:[id], status:"locked"|"open"|"superseded", session:"DS-1" }
```

### `plan/phases.jsonl` (single canonical sequencer)
```
{ id:"CSP-1", title, status:"design"|"impl"|"done", deps:[id], sessions:[DS#], gap:bool, note? }
```

### `plan/backlog.jsonl` (work items + deferred)
```
{ id:"B1", title, state:"open"|"deferred"|"done", trigger?, lang:"all"|"per-package"|"ts"|..., ref? }
```

### `plan/antipatterns.jsonl` (lessons)
```
{ id:"AP1", pattern, why, instead, ref }
```

### `spec/rules.jsonl` (protocol normative rules)
```
{ id:"R-diamond", area, tier?, statement, rationale, status:"active"|"draft"|"amended", since:"D#", covers_by:[conformance-id] }
```

### `spec/conformance.jsonl` (behavioral parity scenarios — replaces structural Impl)
```
{ id:"C-1", name, covers:[rule-id], runtimes:{ts,rust,py}:"todo"|"poc-pass"|"pass"|"fail", status:"required"|"optional", note?, ref? }
```

### `spec/flowcharts.jsonl` (hand-drawn teaching flowcharts; structural ones are auto-generated in Structure view)
```
{ id:"FC-1", title, area, explains:[rule-id|D#], mermaid:"flowchart ..." }
```

### `sessions/sessions.jsonl` (design-session index; bodies are markdown in sessions/{active,archive}/)
```
{ id:"DS-1", title, status:"active"|"archived", opened, locks:[D#], path, supersedes:[id], note? }
```

### `guide/guide.jsonl` (prose guide chapter index)
```
{ id:"G-composition", title, path, lang, area, status, migrate_from? }
```

## Dashboard views (build.mjs → dashboard.html)

| view | content | answers |
|---|---|---|
| **Dashboard** | phase status distribution / progress / recent decisions / gap counts | where is the progress |
| **Gaps** | phases(gap) · open decisions · deferred backlog · rules with no conformance · conformance runtimes=todo · **broken links / orphans** | where are the remaining gaps |
| **Structure** | phase deps DAG + rule→conformance coverage matrix + D#↔session↔phase chain + flowcharts.jsonl rendering | what the structure looks like |
| **Search** | full-text index of all jsonl + markdown bodies | quick lookup |

### CSP-8 Workbench Tab

The **Workbench** view is generated dashboard-private fixture data, not a new jsonl
source of truth and not a public Canvas / WorkspaceGraph API contract. `build.mjs`
owns the fixture fact ledger; `dashboard.js` progressively derives board, detail,
issue, audit, action, and inspector projections from those facts; `dashboard.css`
owns the presentation.

Workbench actions append visible command/request/action facts to the in-page ledger,
then the UI re-derives from the ledger. The fixture may use Layer C vocabulary
such as WorkItem, AgentRequest, ExecutorRoute, ExecutorProfile,
ToolProviderExecutionPolicy, ToolProviderAdapterInput, run request, outcome,
evidence, DataIssue, and audit material, but runtime clients, subprocess handles,
credentials, SDK objects, raw provider payloads, large stdout/stderr/diffs, and
provider-private errors stay out of graph-visible DATA.

WorkbenchCommand, CommandResult, ProjectorRun, ViewProjection, and provenance-edge
facts are dashboard-private trace material. They explain how visible actions produce
derived facts and UI projections; they are not public Canvas commands, provider
runtime APIs, WorkspaceGraph ownership, or protocol behavior.

## Consistency checks (run on every build — fixes P4 stale-premise + P6 link-rot)

- every `sessions.locks` D# exists in decisions.jsonl
- every `phases.sessions` DS# exists in sessions.jsonl
- every `decisions.supersedes` / `rules.since` D# resolves
- every `conformance.covers` rule-id exists in rules.jsonl
- every `flowcharts.explains` id resolves (rule or D#)
- gap: rules with empty `covers_by` AND no covering conformance scenario
- orphan: decision referenced by no session/phase; session producing no decision

## Run

```
node dashboard/build.mjs            # → dashboard/dashboard.html (+ prints consistency report)
node dashboard/build.mjs --check    # consistency report only, non-zero exit on broken links
```
